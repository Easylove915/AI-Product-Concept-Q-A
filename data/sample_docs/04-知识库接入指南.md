# 知识库接入指南

答疑系统的知识库以文档仓库为唯一事实来源。文档变更后需要重新同步，系统才会看到新内容。

## 支持的文档格式

当前接入层支持 `.md`、`.markdown`、`.txt`、`.rst` 与 `.docx`。Markdown 会按标题层级切分章节，DOCX 通过标准库解析段落与 Heading 样式。PDF 属于二进制格式，需要额外安装解析库后扩展接入层，默认扩展名白名单里不包含它。

可以通过配置项 `GITHUB_EXTS` 调整白名单，用英文逗号分隔。同步时会自动跳过 `node_modules`、`.git`、`vendor`、`assets` 等目录。

## 从 GitHub 拉取文档

把仓库地址填成 `owner/repo` 或完整 URL，并指定分支与子目录。系统通过 GitHub 文件树接口枚举文件，再逐个抓取原文，因此只同步白名单内的文档，不会克隆整个仓库。

公开仓库无需凭据，但 GitHub 对匿名请求有速率限制。私有仓库必须配置 `GITHUB_TOKEN`，令牌需要目标仓库的 `Contents: Read` 权限。配置令牌后，拉取会改走 GitHub Contents API 并用 base64 解码，从而支持私有仓库。

如果只想同步仓库里的某个目录，把 `GITHUB_PATH` 设为该目录相对路径，例如 `docs`。留空则扫描整个仓库。

## 分块参数

`CHUNK_SIZE` 默认 600 字符，`CHUNK_OVERLAP` 默认 100 字符。分块优先在段落、句号等自然边界处切断，并把所属标题路径拼进片段开头，避免脱离上下文。

经验值：概念性文档用 500–800 字符，API 参考类文档用 300–500 字符；重叠量取块大小的 15%–20%。块太大稀释检索信号，块太小容易切断完整语义。调整参数后必须重新同步才会生效。

## 检索与答案模式

默认使用 BM25 加 TF-IDF 余弦的混合检索，通过 RRF 融合排序。不配置大模型密钥时，系统返回带引用编号的抽取式答案；配置 `LLM_API_KEY` 后切换为生成式答案，并强制模型用 `[编号]` 标注每个事实的来源。

同一篇文档最多保留 3 个片段进入上下文，防止一篇长文档垄断答案。所有引用编号都会经过校验，指向不存在片段的编号会被剔除并给出警告。

## 文档编写建议

写文档时尽量做到一节一事，标题能独立表达含义；把关键数值、错误码、配置项写成明确的短句，避免用「同上」「参见前文」这类依赖上下文的指代。这类写法对人和对检索器都更友好。
