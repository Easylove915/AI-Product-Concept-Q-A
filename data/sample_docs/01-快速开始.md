# Atlas 网关快速开始

Atlas 网关是团队统一的 API 入口，负责鉴权、限流、路由与可观测性。本文带你在 10 分钟内发出第一个请求。

## 环境要求

- Python 3.10 及以上，或 Node.js 18 及以上
- 一个有效的团队账号，且已被授予 `gateway:call` 角色
- 内网可访问 `https://atlas.internal.example.com`

不要在客户端代码里硬编码令牌。所有示例都从环境变量读取凭据。

## 获取访问令牌

在管理后台的「开发者设置 → 访问令牌」页面创建令牌，令牌只会在创建时完整显示一次。创建后把它写入环境变量：

```bash
export ATLAS_TOKEN="atk_xxxxxxxxxxxxxxxx"
```

令牌默认有效期 90 天，到期前 7 天会发送站内提醒。轮换令牌时建议新旧令牌并行使用 24 小时，避免线上请求中断。

## 发出第一个请求

网关统一使用 `Authorization: Bearer` 头传递令牌，所有业务接口都以 `/v1` 为前缀：

```bash
curl https://atlas.internal.example.com/v1/ping \
  -H "Authorization: Bearer $ATLAS_TOKEN"
```

成功时返回 HTTP 200 与 JSON 体 `{"status":"ok","region":"cn-north-1"}`。`region` 字段表示实际处理请求的机房，排障时请一并记录。

## 客户端超时与重试

推荐把连接超时设为 3 秒、读取超时设为 10 秒。遇到 5xx 或网络错误时采用指数退避重试，最多 3 次，退避基数 200 毫秒。注意 4xx 错误不要自动重试，这类错误是请求本身的问题，重试不会成功。

不要在重试逻辑里忽略 429 状态码，它需要专门的退避策略，参见《限流与配额》。
